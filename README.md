# hxwl-01 可排期听力验配台

门店听力师的分频验配记录、排期与复诊复核工作台。

## 技术栈

React 19 + Vite + TypeScript + 纯 CSS；数据持久化在 localStorage（含模拟"服务端"基线），无后端依赖。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:5101
npm test           # 规则/合并/reducer 联动冒烟测试（42 项断言）
npm run typecheck
```

## 业务规则实现

### 1. 分频验配单（`src/domain.ts`、`RecordsView`）
- 每份验配单按 **左/右耳 × 6 个分频点（0.25–8 kHz）** 分别保存气导、骨导听阈，另有言语识别率、机型、增益、反馈。
- 自动计算双耳 PTA（0.5/1/2/4k 气导均值）与逐频气骨导差。
- 保存后按结果给出建议：复诊间隔（异常 3 天 → 重度 7 天 → 中度 14 天 → 轻度 30 天），并自动在空闲时段排出复诊与试戴建议单。

### 2. 排期约束（`ScheduleView`）
- 验配间 × 时段矩阵；同一客户同一时段**只能占一个验配间**（跨间也拒绝），房间同时段不重复占用。
- **改期先释放原时段**（原单留痕为"已释放"），新时段生成待确认单。
- 同步合并若发现双端撞单，按"已确认优先、同级别创建早优先"自动释放并留痕。

### 3. 复测失效与重确认
- 每张试戴单绑定所依据验配数据的**签名**（`recordSignature`）。
- 复测结果改动后，所有未确认（proposed）的试戴单自动置为"已释放：复测结果改动，需重新确认"；重新排期后再走确认闸口。

### 4. 复核闸口（`ReviewView`）
- 触发条件（阈值在 `DEFAULT_THRESHOLDS`，可配）：
  - 两耳 PTA 差 ≥ 15 dB 或任一分频两耳差 ≥ 20 dB → "两耳参数不一致"；
  - 任一耳任一频气骨导差 ≥ 10 dB → "气骨导差超阈值"。
- 命中即自动生成待复核单（含原因、耳别、数据签名）。
- **复核结论没回来之前试戴不能确认**（确认按钮禁用并给原因）；结论为退回同样拦截；结论回来且签名一致才放行。
- 结论返回后数据再次变化，旧结论失效、重新生成待复核单。

### 5. 断网暂存与合并（`sync.ts`、`SyncView`）
- 断网时所有保存/排期/复核操作进入**本地队列**（页面顶部可一键模拟断网/恢复，也响应浏览器 online/offline 事件），恢复后自动或手动合并。
- 合并按 **三向（本地 / 服务端 / 上次基线）+ 耳级** 进行：只有某只耳两端都改且不一致才挂冲突，单端改动快进合并。
- **复核结论优先**：同一复核单合并时一律以服务端结论为准，本地未同步结论被覆盖会写日志。
- **冲突清单**给出客户、耳别、两次录入时间及分频对照，人工选择采用哪一版；裁决前该客户试戴不能确认。
- "断网与冲突"页提供模拟工具：另一终端服务端复测（制造冲突）、助理服务端批复（演示结论优先）、重置演示数据。

## 代码结构

```
src/
  types.ts        领域模型
  domain.ts       PTA/气骨导差/复核规则、签名、排期碰撞工具
  sync.ts         模拟服务端、三向耳级合并、复核优先、撞单裁决
  store.tsx       reducer：保存联动、复核闸口、失效、同步编排、持久化
  seed.ts         三个示例客户（含单侧传导性损失的复核案例）
  components/      验配单 / 排期台 / 复核台 / 同步冲突中心
test/             纯逻辑冒烟测试（Node + esbuild 打包）
```
